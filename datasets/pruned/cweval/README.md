# CWEval static-model evaluation bundle

Generated by `localScripts/prepare_cweval_datasets.py` from the three Parquet
files now stored in `datasets/raw/CWEval/`.
All 52 tasks (104 implementations) are converted into
`catalog.jsonl`. The two model CSVs contain the same 58 eligible functions
(29 complete reference/unsafe pairs), in the same order.

| Source file | Tasks | Catalog records | Model CSV records |
| --- | ---: | ---: | ---: |
| core_c-00000-of-00001.parquet | 20 | 40 | 16 |
| core_cpp-00000-of-00001.parquet | 21 | 42 | 20 |
| lang_c-00000-of-00001.parquet | 11 | 22 | 22 |

The compatible C and C++ subsets are combined as one external evaluation set.
They remain separate from PrimeVul and LLMVul. Language, source subset, CWE,
pair and related-problem group IDs are retained for stratified reporting.

## Files and labels

- `catalog.jsonl`: every candidate, original code block, extracted function,
  provenance, source matching, token counts, cleaner checks and exclusions.
- `excluded.csv`: 46 excluded records, with each variant's own reasons and
  the union of reasons that excludes its entire pair.
- `manifest.json`: input/output hashes, pinned source and tokenizer revisions,
  software versions, selection counts and protocol identity.
- `../linevul/cweval_test.csv`: `sample_id`, `processed_func`, `target`, blank
  `flaw_line` and `flaw_line_index`, plus metadata. Function classification only.
- `../vulberta/cweval_test.csv`: `sample_id`, `func`, `label`, plus metadata.
- `UPSTREAM_LICENSE`: CWEval's Apache 2.0 license.

`completion` receives label **0** (upstream reference implementation);
`y_negative` receives label **1** (upstream intentionally unsafe implementation).
These labels are supported by comparing parsed function tokens to the official
`_task` and `_unsafe` sources, not by inferring safety from the field names.
All 104 target functions match. Reference means the benchmark's intended
solution for its specified CWE; it does not prove absence of every vulnerability.
No benchmark security tests or model inference were run during conversion.
These are benchmark implementations, not verified LLM-generated samples.

## Extraction and selection

The upstream `BEGIN SOLUTION` marker identifies the target function. C/C++ syntax
trees extract that function and remove comments, including label-bearing hints,
without treating strings as comments. Prompts, includes, surrounding helper
definitions and `main()` harnesses are not model input. Blank annotation lines
and trailing whitespace are removed; lexical token equality is checked.
Original snippets remain in the catalog.

Both variants must match upstream, parse, and have no detected dependence on
omitted local helpers, macros, types or globals. Context detection is conservative;
it is not a compiler/linker check, and standard or external library APIs remain.
Both variants must also survive the **existing** VulBERTa regex cleaner without
lexical changes, and fit LineVul's 512-token and VulBERTa's 1,024-token limits,
including special tokens. Identical functions with opposing labels are excluded.
The model implementations and preprocessing rules are unchanged. VulBERTa's
unknown-token counts are recorded, but unknown tokens do not trigger exclusion.

| Pair exclusion reason | Pairs affected |
| --- | ---: |
| `requires_local_context` | 21 |
| `vulberta_cleaner_changes_code` | 6 |
| `identical_function_conflicting_labels` | 1 |
| `linevul_truncation` | 10 |
| `vulberta_truncation` | 2 |

Reasons overlap. An otherwise eligible variant is also excluded when its partner
fails a check, preserving label balance and a common comparison set for both
models. The selected set contains 22 CWEs and
22 related-problem groups. It is a filtered diagnostic evaluation,
not a representative score for all CWEval tasks or for LLM-generated code.

Both variants, C/C++ counterparts and token-identical functions share `group_id`.
No train/validation split was created. The completed uncertainty analyses preserve
these groups because rows are not independent observations. Predictions join to
the input CSV by `sample_id` for language, CWE, and pair metadata.
The completed [dataset-quality audit](../../../results/diagnostics/dataset_quality/rq1_priority4_diagnostics.md)
and [overlap analysis](../../../results/diagnostics/generalization_controls/rq1_priority5_diagnostics.md)
cover cross-dataset matches and documented training/validation overlap.
Pretraining exposure was not exhaustively established.

## Reproduce and run

Complete the [local environment and pinned-model setup](../../../localScripts/README.md)
first. Run these PowerShell commands from the repository root. Git LFS files
must be present, and text files must retain the audited bytes (see the
[clone instructions](../../../README.md#walkthrough)).

### Evaluate the delivered cohort

Stage a fresh copy in the runner's expected `prepared_datasets/` layout and
populate its cache with the supplied, audited tokenizer snapshots:

```powershell
New-Item -ItemType Directory -Force .\reproductions\cweval_input\prepared_datasets\linevul, .\reproductions\cweval_input\prepared_datasets\vulberta, .\localScripts\.cache\huggingface\hub | Out-Null
Copy-Item -LiteralPath .\datasets\pruned\cweval -Destination .\reproductions\cweval_input\prepared_datasets -Recurse
Copy-Item -LiteralPath .\datasets\pruned\linevul\cweval_test.csv -Destination .\reproductions\cweval_input\prepared_datasets\linevul
Copy-Item -LiteralPath .\datasets\pruned\vulberta\cweval_test.csv -Destination .\reproductions\cweval_input\prepared_datasets\vulberta
Copy-Item -Path .\localScripts\upstream\huggingface\models--* -Destination .\localScripts\.cache\huggingface\hub -Recurse -Force
.\localScripts\.venv\Scripts\python.exe .\localScripts\pivd_local.py --jobs cweval --device cuda --data-root .\reproductions\cweval_input --run-dir .\localScripts\results\rq1_cweval
```

Use `--device cpu` for a CPU environment. The runner verifies the CSV hashes,
preprocessing, and tokenizer assets before inference. Model weights are downloaded
if absent. Expected output: two 58-row evaluations in
`localScripts/results/rq1_cweval/`. The saved F1 values are 0.0 for LineVul and
0.57142857 for VulBERTa. Pair-level correctness is reported separately in the
[consolidated report](../../../results/findings/rq1_answer.md#cweval-pair-analysis).

### Rebuild the cohort from raw Parquets

Install the conversion dependencies and run the converter from this checkout.
It finds the supplied upstream source and tokenizer snapshots directly, so this
rebuild is offline after dependencies are installed. Use a fresh output directory.

```powershell
.\localScripts\.venv\Scripts\python.exe -m pip install -r .\localScripts\requirements-cweval.txt
.\localScripts\.venv\Scripts\python.exe .\localScripts\prepare_cweval_datasets.py --output-root .\reproductions\cweval_rebuild\prepared_datasets
```

An existing runtime tokenizer cache takes precedence over bundled snapshots. Expected counts:
52 tasks, 104 candidates, 58 selected functions, and 29 selected pairs.
Compare generated CSV hashes with `output_sha256` in the supplied
[manifest](manifest.json). To evaluate the rebuilt cohort, use
`--data-root .\reproductions\cweval_rebuild` and a fresh `--run-dir`.
